## Problem

HTI Group needed one chatbot that could both answer from scattered HR knowledge and act for employees — and then survive the jump from quick demo to enterprise production.

- **Fragmented knowledge** spread across PDF, Word and Excel files, where headers, paragraphs and tables carry different meaning.
- **Off-the-shelf RAG broke down** on complex policy queries that crossed multiple sub-domains: leave, payroll, benefits, tooling.
- **Answers were not enough**: staff also wanted the bot to do things — book a meeting room, calculate income tax, open an IT ticket — and only when they had the right permission.
- **POC-to-production was non-negotiable**: the agent layer had to move to AWS without a rewrite.

A **FastAPI gateway** adds **session memory**, then a **router agent** picks the Knowledge, Action or ChitChat agent, each with its own **ReAct loop**. In the POC, Knowledge tools read Qdrant, MongoDB, Neo4j and HR files. Every path ends in one unified response.
</ArchitectureSection>

<ArchitectureSection
  step="02"
  title="Multi-Agent Router (ReAct)"
  image="/assets/case-studies/hti/02-multi-agent-router.png"
  alt="Multi-Agent Router"
  challenge="Policy questions crossed sub-domains, and actions needed permission checks."
>
The **Knowledge agent** calls vector, full-text, graph and tabular tools **in parallel**, then loops until the context is enough. The **Action agent** asks for missing parameters and runs an **RBAC check** before calling external APIs; a denial returns an authorization error. The **ChitChat agent** uses web search.
</ArchitectureSection>

<ArchitectureSection
  step="03"
  title="Data Ingestion Pipeline"
  image="/assets/case-studies/hti/03-data-ingestion-pipeline.png"
  alt="Data Ingestion Pipeline"
  challenge="Mixed headers, paragraphs and tables break naive chunking."
>
**Docling** parses each file's layout. **Hierarchical semantic chunking** splits large parent chunks into small leaf chunks. An **LLM context injector** adds parent context to each leaf, while an LLM graph extractor turns parents into Neo4j triplets. **BGE-M3** embeds leaves into Qdrant; content and metadata go to MongoDB.
</ArchitectureSection>

**API Gateway** checks OAuth2 / JWT and an ALB feeds **ECS Fargate**, where Chat and Agent services talk over gRPC streaming. Async tool calls run on **AWS Lambda**. **Bedrock** and S3 are reached via **VPC endpoints**; data lives in OpenSearch, Neptune, DocumentDB, RDS and ElastiCache.
</ArchitectureSection>

## Outcome

- **One chatbot that answers and acts** — HR knowledge from PDF, Word and Excel behind a single interface, plus RBAC-checked actions on Discord, meeting rooms, income tax and IT tickets.
- **POC to AWS production without rewriting the agents** — the same LangGraph agents now run on ECS Fargate and Lambda, with local stores swapped for managed AWS services.
- **Private by design** — Bedrock and S3 reached only through VPC endpoints; OAuth2 / JWT checked at the API Gateway.
- **Repeatable delivery** with CI/CD via AWS CDK.
- **Reusable agent and infra patterns** that informed downstream projects at FPT Software.
