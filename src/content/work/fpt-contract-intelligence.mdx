## Problem

- **One mega-prompt** — it hallucinated on unfamiliar clauses and returned different fields run to run.
- **No per-task view** — a regression could not be pinned to prices or headings.
- **Did not scale** — synchronous calls timed out as contract volume grew.

Each capability is an **independent skill**; one request runs one skill end to end. Inside: **Context Funnel** → **agentic loop** on Claude that searches **OpenSearch** only when unsure → **Pydantic** output. **+35% accuracy.**
</ArchitectureSection>

<ArchitectureSection

A skill is a **folder**: Python `tools/` run first, `references/` load **only when the signals match**, and `SKILL.md` always loads. The prompt carries only what this contract needs — **~5× fewer tokens**.
</ArchitectureSection>

**SQS** queues feed **Lambda** workers; a **workflow engine** makes every step retryable and **idempotent**. Failures land in a **DLQ** with a Slack replay button.

## Outcome

- **+35% extraction accuracy** vs the legacy single prompt.
- **~5× fewer tokens** per LLM call through progressive disclosure.
- **Thousands of contracts per batch** on SQS and Lambda.
- **Each skill ships and is tested on its own.**
