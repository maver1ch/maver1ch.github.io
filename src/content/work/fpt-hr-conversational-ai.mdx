## Problem

Covestro's HR assistant was live across countries, but had spent a year in maintenance mode with nothing measured.

- **Guesswork** — no cost metrics, dead dashboards, a broken evaluation pipeline.
- **No production-like DEV** — tests ran on a year-old QA knowledge base.
- **Risky deploys** — merging to `main` shipped to production, with no tests and no `cdk diff`.
- **Monolith** — six hard-coded agents in one Lambda; every prompt change needed a redeploy.
- **No single permission check** — HR-only content could not be published safely.

<ArchitectureSection
  step="01"
  title="Take-over Audit: Measure Before Touching Code"
  image="/assets/case-studies/covestro/images/01-takeover-audit.png"
  alt="The inherited Tailor v1 architecture with measured findings pinned to the knowledge base, the LLM, the guardrail, CloudWatch and CI/CD"
>
I read the system offline first, then used the one window of cloud access to **measure, not fix**, and turned the numbers into a **12-item backlog** with evidence on every line. **Recall@5 52.7%** and **faithfulness 74.5%** showed the lever was what the model sees, not the model. Token metrics were **never emitted**.
</ArchitectureSection>

<ArchitectureSection
  step="02"
  title="LLM Observability: Tracing, Cost & Quality"
  image="/assets/case-studies/covestro/images/02-llm-observability.png"
  alt="One chat turn traced step by step in Langfuse, with personal data masked at the source; traces power token usage, cost tracking, per-step latency, debugging, a golden-dataset baseline and prompt versioning"
  highlight
  challenge="Nobody could say why an answer was wrong, how slow each step was, or what it cost."
>
I integrated **Langfuse** so every turn became one trace, with **tokens, cost and latency per step**. Model **cost comparison** became a query. A **golden dataset** of ~200 HR questions is the baseline, and **personal data is masked** at the source.
</ArchitectureSection>

<ArchitectureSection
  step="03"
  title="Ingestion Pipeline: Chunking & Table Fidelity"
  image="/assets/case-studies/covestro/images/03-knowledge-ingestion.png"
  alt="Hourly ServiceNow ingestion pipeline on AWS: EventBridge, Lambda, SQS with DLQ, DynamoDB, an attachment conversion branch, S3, a chunking Lambda, Bedrock Knowledge Base and OpenSearch"
>
A **full corpus scan** found two faults in one layer. The converter flattened tables, so salary and benefit grids lost their rows and columns, and **fixed-size** chunks cut through them. I rebuilt the converter so **Markdown tables survive**, then moved to **hierarchical, table-aware chunking**: a split that lands inside a table takes the whole table.
</ArchitectureSection>

<ArchitectureSection
  step="04"
  title="Production-like DEV: Mirroring the Production Knowledge Base"
  image="/assets/case-studies/covestro/images/04-kb-mirror.png"
  alt="Cross-account mirror of the production knowledge base into DEV, with a runtime SSM switch between the mirror and the stale QA knowledge base"
  challenge="DEV read a stale QA knowledge base (815 vs 995 articles), so passing on DEV proved nothing."
>
I built a **cross-account, read-only mirror** of the production knowledge base in DEV, synced **by ETag**. An **SSM parameter** picks the live knowledge base at runtime, so the move to **Claude Sonnet 4.5** was proven before it shipped.
</ArchitectureSection>

<ArchitectureSection
  step="05"
  title="Semantic Caching Layer"
  image="/assets/case-studies/covestro/images/05-semantic-cache.png"
  alt="Semantic cache on ElastiCache: questions embedded with Cohere Multilingual v3, cosine match scoped by permission, hits served directly, misses run the RAG path and write back"
  highlight
  challenge="The same questions come in a hundred wordings, and a shared cache could leak across permissions."
>
Questions are embedded with **Cohere Multilingual v3** and matched in **ElastiCache**; at 0.95 similarity or above, the stored answer skips retrieval and the LLM. The **cache key carries the user's permission scope**. Repeats return in **~150 ms** with zero tokens.
</ArchitectureSection>

<ArchitectureSection
  step="06"
  title="HR4HR: Restricted Knowledge Base, No Leakage Window"
  image="/assets/case-studies/covestro/images/06-hr4hr-permissions.png"
  alt="HR4HR: every document labelled at import, a server-side HR check each turn, one filter at a single choke point, and two switches with a five-step rollout that turns the filter on before the HR content"
  highlight
  challenge="134 HR-only articles had to share one index with ~1,000 public ones."
>
Each document carries an `access_level` tag. HR status is checked **server-side on every turn**. One filter sits at a **single choke point** every agent inherits, and it was switched **on before** the first restricted document landed. Non-HR users saw **0 restricted references**.
</ArchitectureSection>

<PhaseMarker label="Phase 2 — Tailor 2.0: platform migration" highlight />

<ArchitectureSection
  step="07"
  title="Tailor 2.0 Platform: Engine + MCP Services"
  image="/assets/case-studies/covestro/images/07-tailor-2-platform.png"
  alt="Tailor 2.0 on AWS: a stateless agent engine on Lambda with agent config in DynamoDB, three MCP services invoked as Lambdas, a tool-audit table and the tailor-core data plane"
>
**Prompts and tools are data, not code.** A **stateless LangGraph engine** owns the conversation loop and guardrails, but never calls a business API. Three **MCP services** (knowledge, ServiceNow, Workday) own the tools, resolve permissions and audit every call. Agents live in **DynamoDB**, so a new source is one service plus one config item.
</ArchitectureSection>

<ArchitectureSection
  step="08"
  title="Release Gates: Quality Parity & Latency"
  image="/assets/case-studies/covestro/images/08-release-gates.png"
  alt="Two release gates: a hand-scored 30-question parity run, then a latency waterfall from 18.6 s to 6.3 s against the legacy 7.7 s"
>
**Parity**: 90 reference questions scored by an LLM judge and reviewed by HR; the new platform matched or beat the old one on **90 / 90**. **Latency**: client timings joined with engine logs exposed **fake streaming**. Three fixes took first token from **18.6 s to 6.3 s**, below the legacy 7.7 s.
</ArchitectureSection>

<ArchitectureSection
  step="09"
  title="Zero-Downtime Cutover Behind an SSM Switch"
  image="/assets/case-studies/covestro/images/09-cutover-ssm-switch.png"
  alt="An SSM switch inside the v1 chat Lambda sends each request either to the IAM-signed agent engine or to the old monolith agents"
  highlight
  challenge="A third-party chat front end we could not change, and no downtime budget."
>
I put one **SSM parameter** in the old chat Lambda, read per request. When on, the Lambda **signs the request with IAM** and forwards it to the new engine; when off, the old agents answer. **One value, no deploy**, with rollback **rehearsed at 34.8 s**.
</ArchitectureSection>

<ArchitectureSection
  step="10"
  title="Data-Plane Ownership Transfer, Zero ID Changes"
  image="/assets/case-studies/covestro/images/10-data-plane-migration.png"
  alt="Knowledge base, OpenSearch collection, tables, buckets and the ingestion pipeline moved from the monolith CDK app to a new data repo by stack refactor and cdk import"
  highlight
  challenge="The knowledge base, OpenSearch collection, tables and ingestion pipeline still belonged to the monolith, and rebuilding meant new ids everywhere."
>
A spike settled it: **move, don't rebuild**. When the first window was **aborted**, **16 probe refactors** found an undocumented CloudFormation rule. The next window moved **11 resources in 45 s**, with **zero id changes** and no re-ingestion.
</ArchitectureSection>

  tradeoff="Phase 1 is prompt and config only; tools, third-party apps and databases come next."

<ArchitectureSection
  step="11"
  title="Agent Canvas: See the Whole System"
  image="/assets/case-studies/agent-configurator/01-agent-canvas.jpg"
  alt="Agent Canvas: every agent and MCP service as a card, with purple lines for handoffs and dashed coloured lines for tool use"
  highlight
  challenge="Only developers could change an agent, and nobody else could see the system."
>
I built **Agent Configurator**: a **React** app, API on **AWS Lambda**, company **SSO**. It **maps every agent and MCP service**, with handoffs and tool use as lines. Drag between agents to add a handoff, or onto a service to pick tools; edits stay drafts.
</ArchitectureSection>

<ArchitectureSection
  step="12"
  title="Edit as a New Version, Checked Like the Engine"
  image="/assets/case-studies/agent-configurator/02-edit-as-new-version.jpg"
  alt="Agent edit form: tools, handoffs, handoff messages, follow-up suggestions and model settings, each with a plain-language label and one-line help"
  challenge="Hand-edited config had already gone wrong twice, once creating an HR case without asking the user."
>
Every field has a **plain-language name** and one line of help, tools come **live from the engine**, and a change note is required. Each save is checked with **the engine's own rules**. Saving **only appends a new version**; nothing is overwritten.
</ArchitectureSection>

<ArchitectureSection
  step="13"
  title="Diff, Activate, Roll Back"
  image="/assets/case-studies/agent-configurator/03-agent-versions.jpg"
  alt="Agents list with the active version, number of versions, description and last change for each agent"
  highlight
  challenge="A config change has no pull request and no CI, and goes live on the next message."
>
The **diff** (prompt line by line, tools and handoffs added or removed) is the review. **Activate** test-reads it like the engine, then swaps it in **one atomic step**; production needs the version number typed. **Rollback** means activating an older version.
</ArchitectureSection>

<PhaseMarker label="Across all phases — delivery pipeline" />

<ArchitectureSection
  step="14"
  title="Delivery Pipeline: CI/CD, IaC & LLM Regression"
  image="/assets/case-studies/covestro/images/11-delivery-pipeline.png"
  alt="Before: merging to main deployed straight to production with no tests or infra diff. After: pull-request CI with coverage, a cdk diff gate, DEV deploy through OIDC with smoke tests, an LLM regression suite, and a manual production dispatch"
>
Every pull request runs lint, unit tests with an **80% coverage floor** and a **`cdk diff` against production**; merging deploys to DEV through **GitHub OIDC** with a smoke test. Prompt, model or retrieval changes must pass an **LLM regression suite** before a **manual production release**. Features ship switched off.
</ArchitectureSection>

## Outcome

- **From guesswork to measurement** — baseline, tracing, **19 releases** as sole developer.
- **Repeat questions in ~150 ms**, inside the user's permission scope.
- **HR-only content with zero leakage.**
- **Zero-downtime migration** — parity 90 / 90, first token 18.6 → 6.3 s.
- **Data plane moved with zero id changes**, no re-ingestion.
- **Business in control** — the product owner and HR create simple agents themselves with Agent Configurator.
