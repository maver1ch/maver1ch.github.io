## Problem

Covestro's HR assistant was live across countries, but had spent a year in maintenance mode with nothing measured.

- **Guesswork** — no cost metrics, dead dashboards, a broken evaluation pipeline.
- **No production-like DEV** — tests ran on a year-old QA knowledge base.
- **Risky deploys** — merging to `main` shipped to production, with no tests and no `cdk diff`.
- **Monolith** — six hard-coded agents in one Lambda; every prompt change needed a redeploy.
- **No single permission check** — HR-only content could not be published safely.

**Langfuse** traces every turn: **tokens, cost and latency per step**, a **golden dataset** of ~200 questions as the baseline, and **personal data masked** at the source.
</ArchitectureSection>

Tables were flattened, and **fixed-size** chunks cut through them. I rebuilt the converter so **Markdown tables survive**, then moved to **hierarchical, table-aware chunking**.

<ArchitectureSection
  step="04"
  title="Production-like DEV: Mirroring the Production Knowledge Base"

>
A **cross-account, read-only mirror** of the production knowledge base in DEV, synced **by ETag** and chosen by an **SSM parameter** at runtime.
</ArchitectureSection>

<ArchitectureSection
  step="05"
  title="Semantic Caching Layer"
  image="/assets/case-studies/covestro/images/05-semantic-cache.png"
  alt="Semantic cache on ElastiCache: questions embedded with Cohere Multilingual v3, cosine match scoped by permission, hits served directly, misses run the RAG path and write back"
  highlight

>
**Cohere** embeddings matched in **ElastiCache** at **≥ 0.95** similarity; the **cache key carries the user's permission scope**. Repeats return in **~150 ms** with zero tokens.
</ArchitectureSection>

<ArchitectureSection
  step="06"
  title="HR4HR: Restricted Knowledge Base, No Leakage Window"
  image="/assets/case-studies/covestro/images/06-hr4hr-permissions.png"
  alt="HR4HR: every document labelled at import, a server-side HR check each turn, one filter at a single choke point, and two switches with a five-step rollout that turns the filter on before the HR content"
  highlight
  challenge="134 HR-only articles had to share one index with ~1,000 public ones."
>
A **server-side HR check** on every turn and one filter at a **single choke point**, switched **on before** restricted content landed. **0 restricted references** reached non-HR users.
</ArchitectureSection>

<ArchitectureSection

**Prompts and tools are data, not code.** A **stateless LangGraph engine** runs the loop and guardrails; **MCP services** (knowledge, ServiceNow, Workday) own the tools and audit every call; agents live in **DynamoDB**.
</ArchitectureSection>

<ArchitectureSection
  step="08"
  title="Release Gates: Quality Parity & Latency"
  image="/assets/case-studies/covestro/images/08-release-gates.png"
  alt="Two release gates: a hand-scored 30-question parity run, then a latency waterfall from 18.6 s to 6.3 s against the legacy 7.7 s"
>
**Parity**: 90 questions scored by an **LLM judge**, reviewed by HR — **90 / 90**. **Latency**: fixed fake streaming, first token **18.6 s → 6.3 s** (legacy 7.7 s).
</ArchitectureSection>

<ArchitectureSection
  step="09"
  title="Zero-Downtime Cutover Behind an SSM Switch"
  image="/assets/case-studies/covestro/images/09-cutover-ssm-switch.png"
  alt="An SSM switch inside the v1 chat Lambda sends each request either to the IAM-signed agent engine or to the old monolith agents"
  highlight
  challenge="A third-party chat front end we could not change, and no downtime budget."
>
One **SSM switch** in the old chat Lambda sends each request to the new engine or the old agents. **No deploy to switch**; rollback **rehearsed at 34.8 s**.
</ArchitectureSection>

<ArchitectureSection
  step="10"
  title="Data-Plane Ownership Transfer, Zero ID Changes"
  image="/assets/case-studies/covestro/images/10-data-plane-migration.png"
  alt="Knowledge base, OpenSearch collection, tables, buckets and the ingestion pipeline moved from the monolith CDK app to a new data repo by stack refactor and cdk import"
  highlight
  challenge="Rebuilding the data plane meant re-ingesting everything and new ids everywhere."
>
**Move, don't rebuild.** After one aborted window and **16 probe refactors**, **11 resources moved in 45 s** — **zero id changes**, no re-ingestion.
</ArchitectureSection>

<ArchitectureSection
  step="12"

>
A plain-language form, tools **live from the engine**, every save checked with **the engine's own rules**. Saving **only appends a version** — nothing is overwritten.
</ArchitectureSection>

<ArchitectureSection
  step="13"
  title="Diff, Activate, Roll Back"
  image="/assets/case-studies/agent-configurator/03-agent-versions.jpg"

The **diff** is the review. **Activate** test-reads like the engine and swaps in **one atomic step**; production needs the version number typed. **Rollback** = activate an older version.
</ArchitectureSection>

## Outcome

- **From guesswork to measurement** — baseline, tracing, **19 releases** as sole developer.
- **Repeat questions in ~150 ms**, inside the user's permission scope.
- **HR-only content with zero leakage.**
- **Zero-downtime migration** — parity 90 / 90, first token 18.6 → 6.3 s.
- **Data plane moved with zero id changes**, no re-ingestion.
- **Business in control** — the product owner and HR create simple agents themselves with Agent Configurator.
