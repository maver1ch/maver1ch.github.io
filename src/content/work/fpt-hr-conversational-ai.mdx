## Problem

Covestro AG's HR assistant was already serving employees in production — but it had been in maintenance-only mode for about a year, and nobody was measuring it. Every layer was a liability.

- **Nothing was measured** — retrieval recall sat at 52.7% on the first baseline, token/cost metrics were defined but never emitted, and most dashboards were over a year stale.
- **Data quality broke retrieval** — the HTML converter flattened every table in the knowledge base, so salary and benefit tables lost their rows and columns.
- **PII compliance was an architectural constraint** — production traces and logs could not carry user content, which shaped the whole observability design.
- **Permissions were coarse** — article visibility depended on country and legal entity, with no way to publish HR-only content safely.
- **Downtime was not an option** — every change had to ship against live production traffic.

A bird's-eye view of the full platform. The frontend talks to an API gateway, which fans into the **LangGraph multi-agent core**. The agent layer reads and writes through a data plane built on **OpenSearch** (semantic + lexical retrieval), **RDS** (structured HR records), **S3** (document store), and **ElastiCache** (semantic cache). **AWS Bedrock** is the single LLM gateway — one integration, multiple model providers.
</ArchitectureSection>

<ArchitectureSection
  step="02"
  title="Regular Chat Flow"
  image="/assets/case-studies/covestro/images/2-regular-chatflow.png"
  alt="A normal user chat turn through the LangGraph state machine"
>
The happy path for a single user turn. A request enters the router agent, which classifies the intent and **selects the right sub-agent** (policy, leave, payroll, benefits). The selected agent retrieves grounded context, reasons over it, and emits a response checked against guardrails before it ever reaches the user. The full state machine is **LangGraph-native** so every transition is traceable.
</ArchitectureSection>

<ArchitectureSection
  step="03"
  title="Data Ingestion Pipeline"
  image="/assets/case-studies/covestro/images/3-data-ingestion.png"
  alt="Event-driven HR document ingestion pipeline on AWS"
>
HR documents from Workday and the knowledge base land in **S3**, which fires events into **Lambda** chunkers via **SQS**. Chunks are embedded and written to **OpenSearch** alongside their metadata. The pipeline is fully asynchronous and retries on failure — bursty ingest from policy updates no longer blocks the live serving path.
</ArchitectureSection>

<ArchitectureSection
  step="04"
  title="Workday SSO Auth Flow"
  image="/assets/case-studies/covestro/images/4-workday-auth-flow.png"
  alt="Enterprise SSO via Workday for per-user context isolation"
>
Enterprise SSO is non-negotiable at Fortune 500 scale. The platform federates with **Workday** for identity, exchanges tokens at the gateway, and carries a per-user context through every downstream agent call. This isolates HR data per employee and makes audit trails clean.
</ArchitectureSection>

<ArchitectureSection
  step="05"
  title="Semantic Caching Layer"
  image="/assets/case-studies/covestro/images/5-semantic-cache.png"
  alt="ElastiCache + embedding similarity for semantic response caching"
  highlight
  challenge="HR questions repeat constantly, but phrased a hundred different ways. A plain key cache never hits — and in a system where article visibility depends on country and role, a shared cache is also a leak waiting to happen."
>
Query logs showed roughly **85% of questions clustered on the same set of knowledge articles**, asked in many different wordings and languages — a plain key cache would never hit. Incoming questions are embedded with the same **Cohere Multilingual v3** model used by the knowledge base and matched against **ElastiCache (Redis)** by cosine similarity; above **0.95** the answer is served straight from cache, skipping retrieval and the LLM entirely. Misses run the normal RAG path and write back with a **24h TTL**, matching the hourly ingestion cycle. Two rules make it safe: PII is masked before anything is cached, and the **cache key carries the user's permission scope**, so a cached answer can never cross a country or legal-entity boundary. The threshold was the hard part — too loose serves the answer to a *similar but different* question, too tight makes the cache useless.
</ArchitectureSection>

<ArchitectureSection
  step="06"
  title="Observability & Evaluation Loop"
  image="/assets/case-studies/covestro/images/6-langfuse-evaluation.png"
  alt="Langfuse tracing plus a RAGAS evaluation pipeline scored by an independent judge model"
  highlight
>
Multi-agent failures are invisible to unit tests, so tracing and evaluation are two separate jobs here. **Langfuse** carries the traces — agent routing, model, tokens, latency — with user ids hashed reversibly and **content dropped in production**, because compliance forbids reading production conversations; debugging happens by replaying the same question in DEV plus non-PII breadcrumbs. **Evaluation** is its own pipeline: a **RAGAS** run scored by a judge model on **Bedrock** deliberately different from the chat model to avoid self-bias, plus a deterministic recall@k harness that checks whether retrieval returned the right article at all — no LLM opinion involved.
</ArchitectureSection>

<ArchitectureSection
  step="07"
  title="PII Zero-Trust"
  image="/assets/case-studies/covestro/images/7-pii-zero-trust.png"
  alt="Real-time PII redaction and zero-trust between microservices"
  highlight
  challenge="At Fortune 500 scale, PII leaking into logs, caches, or a stray LLM call is a compliance incident, not a bug. The system needed PII boundaries that hold by construction, not by policy."
>
Compliance is an architectural constraint, not a feature. PII is **redacted at the boundary** — before logs, before the semantic cache, before any Bedrock call. Between microservices, every hop authenticates and authorizes from scratch (**zero-trust**). The latency cost is real but bounded; the upside is eliminating entire classes of compliance incidents.
</ArchitectureSection>

## Outcome

- Migrated production HR conversational workload for a **Fortune 500 client** with no downtime.
- **Established the first quality baseline** on a system nobody had measured, and turned it into an evidence-backed backlog.
- **Semantic caching** answers repeat questions in ~150 ms with zero LLM tokens, inside the user's permission scope.
- **Tracing and evaluation split cleanly**: Langfuse traces with content dropped in production, RAGAS plus a deterministic retrieval harness as the quality gate.
- **Server-side permission filtering** (fail-closed, single choke point) shipped an HR-only knowledge base with no leakage window at any stage of rollout.
- **Workday SSO** integrated cleanly for per-user context isolation across the agent layer.
